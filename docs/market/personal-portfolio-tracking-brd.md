# 个人持仓与收益追踪 BRD

## 1. 文档状态

- 状态：范围校正版，待产品确认
- 产品名称：Personal Portfolio（个人持仓）
- 业务归属：`cynexus-market` 新增独立 `portfolio` bounded context
- UI 位置：侧边栏 Stock Overview 的下一项，不嵌入 Stock Overview 页面
- 首期输入：用户上传一张交易记录截图，系统异步解析

## 2. 一句话定义

Personal Portfolio 是一套以“用户确认过的交易”为事实来源的个人投资账本：用户上传交易截图，AI 异步生成候选交易，用户校对确认后，系统更新持仓和收益，并把买卖点与复盘放回个股行情上下文。

它不负责预测、荐股或代替券商账户，也不复用 Finance Capture、Stock Review、Media Transcription 的业务模型。

## 3. 用户问题

目标用户是使用券商截图记录 A 股交易、希望在 Cynexus 中持续跟踪结果并进行盘后复盘的个人投资者。

需要解决的核心问题：

1. 交易记录散落在券商截图中，手工录入成本高。
2. AI 识别可能出错，不能让未确认结果直接改变持仓。
3. 用户能看到行情，却难以把真实买卖点和当时决策放在一起复盘。
4. 券商提供当前持仓，但不便沉淀跨时间的交易理由、执行偏差和经验。
5. 只有成交记录时无法严谨计算完整账户收益率，产品必须避免给出误导性的数字。

## 4. 产品原则

- AI 只提取候选事实，不替用户确认交易。
- 只有用户明确确认的交易才影响持仓和收益。
- 原截图、AI 结果、用户修改和最终交易保持可追溯关系。
- 持仓和收益采用确定性计算，不由模型计算。
- 页面离开后解析继续；用户再次进入时可恢复任务状态。
- 收益字段必须写清口径、行情日期和不可用原因。
- 首期只做一个个人投资账本，不引入多组合管理。

## 5. MVP 范围

### 5.1 截图上传与异步解析

- 一次上传一张 PNG、JPEG 或 WebP 截图。
- 一张截图可包含一笔或多笔交易记录。
- 上传成功后立即返回任务标识，不等待 AI 完成。
- 用户可离开页面；任务状态和结果由服务端保存。
- 支持的任务状态：
  - `UPLOADED`：文件已接收，内部可能处于待投递或已进入 RabbitMQ 队列。
  - `PROCESSING`：正在解析。
  - `READY_FOR_REVIEW`：已有候选交易，等待校对。
  - `CONFIRMED`：用户已确认并入账。
  - `FAILED`：解析失败，可查看原因并重试。
  - `CANCELLED`：用户在确认前取消。
- 解析超时、模型异常和非交易截图不能生成虚构交易。
- 任务完成或失败后，页面展示明确状态；首期采用页面内通知，不要求系统级推送。

### 5.2 AI 候选交易

每一候选行包含：

- 证券代码、证券名称。
- 买卖方向：`BUY` 或 `SELL`。
- 成交日期、可选成交时间。
- 成交价格、成交数量。
- 可选成交金额、总费用、成交编号。
- 每个关键字段的置信度、原始文字证据和警告。

识别规则：

- 截图没有出现的值返回空，不允许猜测。
- 证券名称不能替代证券代码自动入账。
- 数量、价格、方向、日期或代码缺失时，该行不能确认。
- AI 原始输出必须经过结构校验和业务校验后才能展示。

### 5.3 人工校对与确认

- 用户可以修改候选字段、排除无效行、保存校对结果并稍后继续。
- 低置信度、金额不一致、证券不存在和疑似重复必须以文字或图标提示，不能只依靠颜色。
- 用户确认前显示将要写入的交易数量和警告摘要。
- 确认是显式操作，并且具有幂等性；重复点击不能产生重复交易。
- 一个任务确认成功后不可再次确认。
- 已确认交易如需修正，使用“更正”操作保留原记录和替代关系，不静默覆盖历史。

### 5.4 持仓与收益

首期范围限定为 A 股、CNY、普通多头买卖，不支持做空。交易按成交时间和稳定 ID 排序，使用移动加权平均成本法。

买入：

```text
买入成本 = 数量 x 成交价 + 买入费用
新持仓成本 = 原持仓成本 + 买入成本
新平均成本 = 新持仓成本 / 新持仓数量
```

卖出：

```text
卖出净收入 = 数量 x 成交价 - 卖出费用
卖出成本 = 卖出数量 x 卖出前平均成本
已实现盈亏 = 卖出净收入 - 卖出成本
剩余持仓成本 = 原持仓成本 - 卖出成本
```

展示指标：

- 当前持仓数量、平均成本、最新价格和当前市值。
- 单个持仓未实现盈亏及未实现收益率。
- 已实现盈亏、未实现盈亏和总盈亏金额。
- 按日展示累计盈亏曲线；无法获得历史行情的日期明确标记缺口。
- 每个数字显示估值日期；行情过期或缺失时展示 `stale` 或 `unavailable`。

只有交易记录时，首期不展示“完整账户累计收益率”。完整账户收益率需要可靠的初始资金、入金、出金、分红和现金余额，否则会产生误导。首期可展示的百分比仅限有明确分母的持仓收益率和已结束交易周期收益率。

业务约束：

- 卖出数量不得大于当时持仓数量。
- 费用只扣减一次；截图未提供费用时按 0 记录并标记来源。
- 持仓、成本和盈亏全部由已确认且有效的交易派生。
- 更正交易后，从受影响的最早日期重新计算。

### 5.5 买卖点

- 从 Personal Portfolio 的持仓行进入标的详情。
- 详情页组合现有行情 K 线和个人交易，不复制行情数据。
- 买点和卖点显示方向、日期、价格和数量。
- 同日多笔交易可聚合显示，并能展开查看明细。
- 点击标记可查看对应交易、来源截图和关联复盘。
- 首期固定一种明确的行情复权口径，并在图表上标注；不得把原成交价伪装为复权价格。

### 5.6 复盘

复盘不是一个孤立备注框，而是关联某只股票和一段交易区间的结构化记录。

首期字段：

- 复盘范围：证券、开始日期、结束日期，可关联区间内交易。
- 交易逻辑：为什么交易、原计划是什么。
- 执行情况：实际买卖是否符合计划、偏差原因。
- 结果快照：系统生成的盈亏、收益率、持有天数和交易次数。
- 结论：做对了什么、错误是什么、下一次行动。
- 标签、1-5 分评分、`DRAFT` 或 `COMPLETED` 状态。

用户可从卖点、标的详情或待复盘区域创建复盘。客观交易结果由系统生成，用户不能用文本字段覆盖。

## 6. 完整工作流

```text
上传一张截图
  -> 立即返回解析任务
  -> 后台异步调用视觉 AI
  -> 生成候选交易
  -> 用户逐行校对并保存
  -> 用户显式确认
  -> 写入交易账本
  -> 重算持仓与盈亏
  -> 在图表显示买卖点
  -> 用户创建并完成复盘
```

关键分界：`READY_FOR_REVIEW` 之前是识别过程，`CONFIRMED` 之后才是投资账本事实。

## 7. 页面与信息架构

侧边栏：

```text
Stock Overview
Personal Portfolio
```

首期页面：

- Portfolio Overview：收益摘要、解析任务状态、持仓表、累计盈亏曲线、待复盘入口。
- Import Review：截图预览、任务状态、候选表格、逐字段校对、确认/重试/取消。
- Position Detail：单只股票持仓指标、行情与买卖点、交易明细、复盘列表。
- Review Editor：结构化复盘编辑、客观结果快照、草稿/完成状态。

Overview 的首屏优先级：待处理任务 > 收益摘要 > 持仓 > 盈亏趋势 > 待复盘。页面保持现有 Cynexus 的安静、紧凑、可扫描风格，不做营销式卡片墙。

## 8. 竞品拆解与取舍

| 产品类型 | 用户已经习惯的能力 | Cynexus 首期吸收 | 首期不复制 |
| --- | --- | --- | --- |
| 券商 App | 成交和持仓数据清晰 | 清晰交易事实、成本和盈亏口径 | 券商登录、下单、账户对账 |
| Sharesight / Portfolio Performance | 可审计账本和绩效 | 交易驱动的确定性持仓与收益 | 多账户、多币种、税务、完整绩效体系 |
| TradingView | 在行情中查看操作点 | K 线叠加真实买卖点 | 社交、策略回测和交易终端 |
| TraderSync / Edgewonk | 结构化交易日志 | 计划、执行、结果、结论闭环 | 大规模行为评分和 AI 教练 |

首期差异化不是“再做一个持仓表”，而是：截图低摩擦导入、AI 与人工确认分离、交易事实可追溯、买卖点和复盘在同一行情上下文中闭环。

## 9. 异常和安全

- 非图片、超限图片或无法解码的图片在上传阶段拒绝。
- 非交易截图、空结果和结构错误进入失败或待人工处理状态，不自动入账。
- 页面刷新、关闭或服务短暂重启后，任务记录和校对结果不能丢失。
- 原截图不得写入普通日志、AI 响应预览或自主 Agent 输出。
- 所有查询和写入按可信 principal + tenant 隔离，前端不能指定 owner。
- 截图需要可配置保留期和用户删除能力；删除证据不删除已确认交易事实。
- 模型只能读取本次任务的图片，不能获得该用户其他持仓或截图。

## 10. 明确不在 MVP

- 多投资组合、多券商账户管理。
- CSV、Excel、PDF 批量导入和券商自动同步。
- 入金、出金、分红、现金余额、TWR、XIRR 和基准对比。
- 港股、美股、基金、期货、期权、多币种、做空和税务。
- AI 自动确认、自动修改交易、自动写复盘或投资建议。
- 自主 Agent 上传截图、确认交易或修改复盘。
- 除已确认的 RabbitMQ 业务消息平台外，为首期引入 Kafka、RocketMQ 或通用工作流引擎。

## 11. 验收标准

- Personal Portfolio 作为独立菜单位于 Stock Overview 下方，具有独立路由和页面目录。
- 单张截图上传立即返回任务，离开页面后可重新打开并恢复状态。
- 一张图可解析多笔候选交易，缺失和低置信度字段明确提示。
- 未确认候选不影响持仓；确认原子、幂等且必须由用户触发。
- 已确认交易能正确计算持仓、平均成本、已实现/未实现盈亏和总盈亏。
- 卖超校验、费用口径、交易排序和更正重算具有领域单元测试。
- 标的详情显示真实买卖点，并可追溯到交易和来源任务。
- 复盘支持草稿、完成、结果快照和从交易上下文进入。
- 行情日期、数据缺失、失败、空状态、处理中和待确认状态均有明确 UI。
- 前端请求代码位于 `cynexus-ui/src/services/market/portfolio/`，不进入 `lib/api.ts`。
- 业务代码属于 `cynexus-market` 的独立 `portfolio` 分层；AI 服务只提供受治理的视觉模型执行能力。

## 12. MVP 默认产品口径

- 资产范围：仅支持 A 股、CNY、普通多头交易。
- 图片保留：原截图默认保留 30 天，用户可提前删除；保留期做成配置，不影响已确认交易事实。
- 复盘提醒：每次卖出后进入待复盘，持仓归零时提高优先级。

这些是首期实现默认值，不扩展多市场、完整账户绩效或自动投资建议范围。
