# DDD Audit 2026-07-23

## Scope

Audited the Java modules in `cynexus-knowledgebase`, `cynexus-market`, `cynexus-core`, and `cynexus-ai` against `guide/DDD-IMPLEMENTATION-GUIDE.md`.

Five parallel read-only audits covered knowledgebase, market, core, AI, and cross-module boundaries. The audit confirmed that the main architectural gap is not a missing repository port; it is business orchestration remaining in application services without a feature-level DomainService entry point.

## Priority Findings

1. Core finance, media transcription, and scheduler use cases contain business state transitions and cross-aggregate rules in Application services.
2. Knowledgebase document and index lifecycle is split across separate services without one lifecycle orchestration boundary or durable index synchronization.
3. Market StockChart, Market Pulse, Industry Application, and Market Sentiment use cases perform normalization, fallback, routing, aggregation, and persistence decisions in Application.
4. AI Agent execution, task lifecycle, model configuration, application analysis, knowledge generation, and media AI flows are implemented in Application services rather than feature DomainServices.
5. Domain modules contain framework dependencies, including Spring annotations and framework types; these prevent isolated domain tests.
6. Core and other starters scan `cn.cccs7.cynexus`, which crosses bounded-context boundaries and can activate unrelated scheduled jobs.
7. `AiModelController` and `AiMarketProbeController` bypass Application use cases; Agent recovery/retention jobs directly manipulate repositories.
8. DomainService-focused tests are sparse and do not cover the principal state machines, routing rules, retry policy, or cross-aggregate invariants.

## Execution Order

Changes are being applied in bounded slices: starter isolation and domain dependency rules first, then knowledgebase, market, core, and AI feature orchestration. Each slice must preserve public API behavior, add focused tests, and be reviewed before a versioned commit. Version files are synchronized by the integrating change rather than edited concurrently by workers.

## Acceptance Evidence

- Every touched use case has a named DomainService under a feature-specific domain package.
- Application services only map commands/DTOs, invoke the DomainService, coordinate transaction boundaries, and map results.
- Domain code has no MVC, API DTO, persistence PO, MyBatis, Spring, Redis, Feign, or Spring AI dependency.
- Controllers and scheduled jobs do not call repositories or infrastructure adapters directly.
- Focused tests pass before full Maven, UI, and versioned Release regression.
