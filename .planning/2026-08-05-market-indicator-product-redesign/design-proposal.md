# Market Indicator 产品重构方案

## 结论

当前模块不应继续围绕“池内广度、行业排行、事件列表”做第三次界面重排。它需要从一个**快照监控页**重定义为一个有完整时间链路的**盘面传导工作台**：

1. 盘中回答：现在的大盘环境是什么，哪个板块正在异动，谁先动，随后有多少同板块股票响应，这次传导是否持续。
2. 盘后回答：当天发生过哪些有效/无效传导，谁是真正的带头股或压制股，信号出现后 5/15/30 分钟及收盘表现如何。
3. 同一套 `MarketContext -> SignalEvent -> SectorEpisode -> Outcome` 数据模型同时服务盘中和盘后，不再维护两套互不一致的解释。

建议保留 `/market/indicator` 路由，页面中文名称改为 **盘面传导**，副标题为 **盘中信号 / 盘后复盘**。`Market Indicator` 可继续作为内部模块名。

## 为什么当前方案不能满足目标

### 已经做得好的部分

- 已明确模块只覆盖近一年涨跌停历史池，没有继续冒充全市场统计。
- 已有实际涨跌停价格、盘口封板判断、快速变化事件、行业聚合、日内首次事件、数据完整性与最新有效快照保护。
- UI 的加载、空、错误、刷新和响应式基础较完整，视觉也符合 Cynexus 的克制工作台风格。

### 关键缺口

- 当前是“最新状态”，不是“先后关系”。有第一事件，但没有后续响应序列。
- 当前是“行业内部统计”，不是“个股对板块的带动或压制”。
- 当前事件只记录股票本身，没有绑定事件时刻的大盘、指数、风格、成交与情绪环境。
- 当前关系分是板块映射置信度与同向涨跌，不是传导或因果证据。
- 当前没有盘后结果评价，无法知道哪些信号有用、哪些只是瞬时噪声。
- 当前事件流逐条展示，用户必须自行把相邻股票、板块和时间拼成一个交易故事。

## 用户任务

### 盘中信号

用户打开页面后，应在 15 秒内完成以下判断：

1. 当前是指数共振、题材活跃、权重护盘、普跌还是缩量分化。
2. 哪些板块刚出现新的拉升或打压，而不是早已涨完/跌完。
3. 板块里谁最先动，谁只是跟随，谁对指数有贡献，谁真正引起了情绪扩散。
4. 这次异动是个股独立行为、单一权重拉动，还是多数成分股正在确认。
5. 是否值得进入板块/个股详情、加入关注或等待第二次确认。

### 盘后复盘

用户选择交易日后，应完成：

1. 沿时间轴回看全天主要板块传导事件。
2. 区分有效传导、冲高回落、单股异动、反向压制和尾盘被动拉升。
3. 查看每个事件出现时的大盘环境，以及事件后的相对收益和持续性。
4. 汇总当天核心板块、核心股、失败信号与次日关注项。

## 产品原则

1. **环境、事件、传导、结果分层。** 全市场环境由 Market Pulse / Market Sentiment 提供；Market Indicator 只负责异动与传导分析。
2. **不把相关性写成因果。** 默认文案使用“领先”“随后扩散”“传导线索”“疑似压制”。只有同时具备时间领先、超额强度、横截面响应和持续性证据时，才显示“高可信带动”。
3. **区分指数贡献与情绪带动。** 大市值股票可抬高行业指数，但未必带动多数成分股；两者必须分别显示。
4. **区分池内发现与全板块确认。** 历史涨跌停池用于发现候选带头股；板块是否被带动，应尽量使用完整行业成分股确认。
5. **所有得分可解释。** 不显示无法展开证据的黑盒 `/100` 分数。
6. **盘中与盘后共享同一事实。** 复盘只能回放当时已知的数据，不能把收盘后信息偷偷带回 10:17 的画面。

## 竞品启示

| 竞品 | 值得吸收的能力 | Cynexus 不应照搬的部分 |
|---|---|---|
| 开盘啦 | 竞价—盘中—复盘连续工作流；板块强度；市场情绪；核心股与高度梯队；可拖动时间轴 | 研究结论不能依赖人工口径或不可解释标签 |
| 同花顺 | 异动提醒与大盘异动、热点板块、资金流同时出现 | 不做高噪声、无优先级的提醒轰炸 |
| 东方财富 | 一行同时给出板块涨幅、主力净流入、领涨股和领涨幅 | “当前领涨”不能直接等同于“率先带动” |
| 通达信 | 自定义筛选、盯盘预警、涨停龙头与快速下钻 | 第一阶段不建设复杂公式编辑器 |
| 财联社 | 异动原因、题材解释和按时间组织的催化信息 | 机器信号与新闻解释必须分栏，避免事后强行归因 |
| TradingView | 历史回放、告警和在指定时间点观察当时数据 | 不在第一阶段建设模拟交易系统 |

## 信息架构

页面顶部使用两个一级模式：

- **盘中雷达**：默认模式，显示实时/延迟状态和最新传导事件。
- **盘后复盘**：选择交易日，按事件时间轴回放并评价结果。

两个模式共享行业、股票和事件详情，不通过完全不同的页面实现。

```text
大盘环境
  -> 板块异动排行
    -> 选择一个传导事件
      -> 带头/压制候选与跟随梯队
      -> 同步分时：个股 / 板块 / 基准指数
      -> 当时环境与催化证据
      -> 盘后结果与复盘结论
```

## 盘中雷达布局

### 1. 顶部控制与状态条

- 模式：盘中雷达 / 盘后复盘。
- 交易日与当前时间；午休、盘后、非交易日需要明确状态。
- 实时性：最后成功采集、数据延迟、覆盖率、当前使用的板块分类。
- 快速筛选：拉升 / 打压、行业 / 题材、最低可信度、只看新事件、只看关注池。
- 自动刷新与手动刷新分开表达。

### 2. 大盘环境带

不是 KPI 卡片墙，而是一条紧凑、可横向比较的环境带：

- 上证、沪深 300、中证 1000、创业板/科创代表指数的当前与 5/15 分钟变化。
- 全 A 上涨/下跌家数、涨跌停、成交额及成交速度。
- Market Sentiment 综合状态与最主要的 2–3 个驱动分量。
- 风格状态：大盘/小盘、成长/价值、权重/题材。
- 当前环境结论，例如“指数弱、题材局部扩散”“权重拉升、广度未确认”。

每个板块事件详情还要保存一份**事件发生时的环境快照**，用于与当前环境对比。

### 3. 板块传导排行（页面主列表）

每一行必须直接回答用户的核心问题：

| 字段 | 含义 |
|---|---|
| 起始时间 / 最近确认 | 事件何时开始，最后一次确认何时发生 |
| 板块 | THS 行业为主；题材作为次级标签 |
| 方向与阶段 | 拉升/打压；萌芽/扩散/拥挤/衰减/失败 |
| 带头或压制候选 | 股票名称、代码、角色类型 |
| 个股信号 | 1/3/5 分钟超额变化、量额加速、涨跌停状态 |
| 板块响应 | 等权变化、去除带头股后的变化、上涨/下跌家数变化 |
| 跟随 | 跟随股票数/有效成分股数、中位响应延迟 |
| 资金与成交 | 板块主力净流、成交额加速度；缺失时不伪造 |
| 市场环境 | 事件发生时的指数/广度简码 |
| 可信度 | 高/中/低，并可展开证据；不是孤立分数 |

默认排序是“新鲜度 × 传导可信度 × 事件强度”，不是单纯按板块涨幅。

### 4. 传导事件详情

选择一行后在同页展开主工作区：

- **同步分时图**：带头股、板块等权指数、板块去带头股指数、适配基准指数，共用时间轴和事件标记。
- **传播梯队**：首动候选 -> 第一批跟随 -> 第二批跟随 -> 未响应/反向股票。
- **角色拆分**：权重贡献型、情绪扩散型、资金引导型、独立异动、反向压制型。
- **证据面板**：时间领先、超额强度、成交确认、响应覆盖、持续性、数据完整度。
- **环境面板**：事件发生时与当前的大盘状态对比。
- **催化面板**：相关公告/新闻/题材，仅作为解释证据，并标注发布时间与来源。
- **动作**：打开股票详情、打开行业详情、加入关注、固定事件。第一阶段不直接提供交易动作。

### 5. 事件流

当前逐条股票事件流改为**事件簇/事件 episode**：

- 同一板块、同方向、相近时间的股票事件合并为一条。
- 展示“09:47 半导体设备由金海通率先拉升，3 分钟内 8/23 只池内股票响应”。
- 单股异动未获得板块确认时单独标记“未扩散”，降低优先级但不隐藏。
- 新事件、二次确认、扩散加速、衰减、反转分别有明确状态更新。

## 盘后复盘布局

### 1. 当日结论

- 大盘环境轨迹：开盘、上午、午后、尾盘四段。
- 最强传导板块、最强压制板块、最大赚钱效应、最大亏钱效应。
- 有效事件数、失败事件数、单股噪声数、平均扩散延迟。
- 核心带头股、核心跟随股、反复开板/冲高回落风险股。

### 2. 全天时间轴

- 横轴为交易时间，纵向分为大盘、板块、股票事件层。
- 支持拖动到任意时间点；页面只展示当时已知的状态。
- 点击事件同步定位分时图、环境快照、传播梯队和结果。

### 3. 事件成绩表

每个板块 episode 显示：

- 事件开始和确认时间。
- 带头候选、跟随数、扩散覆盖率、中位延迟。
- 事件后 5/15/30 分钟板块超额收益。
- 最大有利/不利变动、收盘保留率。
- 结果：持续、冲高回落、延迟扩散、失败、反向。
- 失败原因标签：大盘逆风、无成交确认、仅权重拉动、跟随不足、事件过晚等。

### 4. 次日关注

- 用户可把板块、带头股或失败但有催化的事件加入次日关注。
- 系统提供“为什么进入关注”的证据摘要，不自动给买卖结论。

## 核心分析模型

### 1. Signal Event：单股异动事实

建议从当前“相邻快照涨跌幅变化”升级为包含窗口和基准的事实：

- `window`: 1m / 3m / 5m。
- `returnDelta`: 窗口收益。
- `sectorExcess`: 相对所属板块的超额收益。
- `marketExcess`: 相对适配指数的超额收益。
- `amountAcceleration`: 当前成交额速度 / 同时段基线。
- `volumeAcceleration`: 当前成交量速度 / 同时段基线。
- `turnoverAcceleration`。
- `limitTransition`: 触板、封板、开板等可观察状态。
- `freshness` 与 `dataQuality`。

### 2. Sector Episode：板块传导事件

把同一板块、同方向、时间相近的 Signal Event 聚合：

- `startedAt`, `confirmedAt`, `endedAt`。
- `direction`: rise / fall。
- `stage`: emerging / spreading / crowded / decaying / failed。
- `leaderCandidates` 与 `suppressorCandidates`。
- `respondedCount`, `eligibleCount`, `coverageRatio`。
- `medianLagSeconds`, `p75LagSeconds`。
- `equalWeightReturn`, `exLeaderReturn`, `benchmarkExcess`。
- `breadthDelta`, `amountAcceleration`, `persistenceMinutes`。
- `marketContextAtStart`, `marketContextAtConfirm`。
- `confidenceLevel` 与 `evidenceBreakdown`。

### 3. 带头/压制线索

建议显示五项证据，不先追求一个神秘总分：

1. **时间领先**：候选股票的异常是否显著早于板块聚合变化。
2. **相对强度**：是否明显跑赢/跑输板块与基准指数。
3. **成交确认**：成交额、成交量、换手或盘口是否同步增强。
4. **扩散响应**：其后有多少成分股同向响应，响应延迟多长。
5. **持续性**：去掉该股票后，板块是否仍继续同向运行。

角色判定：

- **情绪带头**：时间领先、跟随广、去除自身后板块仍延续。
- **权重带动**：对加权指数贡献大，但等权广度弱。
- **独立异动**：个股强，但板块未跟随。
- **疑似压制**：个股率先下跌，随后板块广度和中位收益恶化。
- **反向抗跌/抗涨**：板块走弱/走强时保持反向，可作为结构线索。

### 4. 大盘环境快照

事件时刻至少保存：

- 宽基指数 1/5/15 分钟与日内变化。
- 全 A 涨跌家数、涨跌停、成交额速度。
- 市场情绪综合值及关键分项。
- 风格相对强弱。
- 交易阶段：集合竞价、开盘冲击、上午中段、午后开盘、尾盘。

环境只描述“信号发生在什么背景”，不作为事后合理化标签。

### 5. 结果评价

每个 episode 在盘后回填：

- `forwardReturn5m/15m/30m/close`。
- `forwardExcess5m/15m/30m/close`。
- `maxFavorableExcursion`, `maxAdverseExcursion`。
- `coveragePeak`, `persistenceMinutes`, `closeRetention`。
- `outcome`: sustained / faded / failed / reversed / late_spread。

## 数据与系统边界

### 可直接复用

- Market Pulse：全 A 广度、成交额、资金流、宽基指数、1 分钟指数 K 线、风格板块、行业当前领涨股与资金。
- Market Sentiment：综合情绪与九个分项。
- Market Indicator：历史涨跌停池、当前快照、盘口涨跌停状态、快速事件、行业映射。
- 现有行业成分股、THS90/TDX56 映射与股票基础数据。

### 必须补齐

1. 行业/题材与成分股的盘中时间序列，至少 1 分钟粒度。
2. 事件时刻的市场环境快照，而非只有日级情绪。
3. 板块去除带头股后的等权/加权走势。
4. 成分股响应序列与 follower lag。
5. 分钟成交额/成交量同时段基线。
6. episode 持久化与盘后 outcome 回填。
7. 可选的新闻/公告/题材催化匹配。

如果只能使用历史涨跌停池数据，产品必须写“池内传播”；若要写“板块内情绪扩散”，确认层必须覆盖完整行业成分股或达到明确覆盖阈值。

## 建议 API 形态

不要求第一阶段一次完成，但数据边界应按以下资源拆分：

- `GET /api/market/indicator/live/context`
- `GET /api/market/indicator/episodes?tradeDate=&direction=&stage=&minConfidence=`
- `GET /api/market/indicator/episodes/{episodeId}`
- `GET /api/market/indicator/review?tradeDate=`
- `GET /api/market/indicator/replay?tradeDate=&at=`

Overview 不再返回 2500 只股票的一体化大包。列表返回摘要，事件详情按需加载时间序列、成员响应与催化证据。

## 交互模型

- 点击板块 episode：在同页更新详情，不丢失排行与时间位置。
- Hover/键盘移动分时图：同步高亮该时刻的大盘、板块和 follower 事件。
- 点击跟随梯队中的股票：打开股票详情 Drawer；保留 episode 上下文。
- 盘后拖动回放时间：所有列表与分时按 `at` 时间截断。
- 固定事件：可同时比较两个 episode，但第一阶段最多两个，避免多窗口噪声。
- 分数/状态 Hover 或点击：展开证据明细、数据覆盖与计算窗口。

## 页面状态

- 盘前：显示昨日复盘与今日关注，不伪造实时传导。
- 交易中：显示数据延迟、最近确认和新事件标记。
- 午休：冻结时间轴并标识午间状态。
- 盘后：自动切换为“今日复盘可生成/已生成”。
- 非交易日：默认打开最近交易日复盘。
- 数据部分缺失：大盘环境、板块数据、池内信号分别降级，不隐藏其他可用区域。
- 覆盖不足：禁止输出“高可信带动”，显示“样本不足/仅池内线索”。
- 无事件：解释当前筛选范围，允许降低门槛或查看单股未扩散信号。

## 分阶段实施

### Phase 0：指标契约与离线验证

- 先定义 Signal Event、Sector Episode、Market Context、Outcome。
- 用已有若干交易日回放，检查事件数量、重复率、假信号率和覆盖率。
- 明确 1/3/5 分钟窗口和行业分类主口径。

这是必要阶段，避免再次先做页面、后发现指标语义不成立。

### Phase 1：用户工作流重构（利用现有数据）

- 增加盘中雷达 / 盘后复盘两个模式骨架。
- 组合现有 Market Pulse、Sentiment 和 Indicator 数据，补上大盘环境带。
- 板块列表同时展示当前领涨股、板块涨幅、资金流、池内异动和环境。
- 把股票事件聚合成初级 episode，但明确标识“当前领涨/池内领先线索”，不宣称带动。
- 后端拆分 summary/detail，停止轮询 2500 只全量大包。

### Phase 2：真实传导引擎

- 增加完整行业成分股分钟序列、去带头股板块序列和响应梯队。
- 计算时间领先、超额强度、响应覆盖、延迟和持续性。
- 输出可解释的带头/压制角色与 confidence evidence。

### Phase 3：盘后复盘与回放

- episode 持久化、全天时间轴、指定时间点回放。
- 5/15/30 分钟与收盘结果回填。
- 日结论、失败信号、次日关注清单。

### Phase 4：催化与个性化

- 公告/新闻/题材时间匹配。
- 用户关注、提醒阈值和 Agent 查询工具。
- 写操作（关注/备注）遵循预览、确认与审计；交易不在本模块范围内。

## 成功指标

- 用户从打开页面到定位一个值得研究的板块事件不超过 30 秒。
- 80% 以上高可信 episode 能展示完整的时间、相对强度、跟随、持续性和环境证据。
- 单股未扩散事件与板块确认事件明确分开，误读率下降。
- 盘后可以从任意事件还原“当时知道什么”和“后来发生什么”。
- 同一指标在 Python、Java、UI 和 Agent 中只有一个定义。
- API 不再每分钟传输 2500 只全量快照；列表/详情按需加载。

## 设计方向

- **色彩策略**：Restrained，沿用 Cynexus 中性工作台；红/绿只表达 A 股方向，蓝色表达选择/信息，琥珀表达待确认。
- **使用场景**：用户在交易时段的桌面工作台上持续盯盘，注意力紧张，需要一眼区分新事件、已确认和正在衰减的事件；盘后在同一台设备上回放和做次日准备。
- **参考锚点**：开盘啦的盘中—复盘连续性、东方财富的板块—领涨—资金同排表达、TradingView 的时间回放。
- **界面原则**：保留 WorkspaceShell、稳定密度、表格优先、单层 panel、同步时间轴；不做卡片墙、营销式大数字、装饰动画或黑盒分数。

## 本轮范围

- 交付级别：产品方案与中保真信息架构，不写应用代码。
- 覆盖范围：完整 Market Indicator surface，包括盘中、盘后、详情和数据契约。
- 交互说明：定义关键交互和状态，但不生成高保真视觉稿。
- 后续门禁：确认以下产品假设后，再进入详细数据设计和实现拆分。

## 需要确认的产品假设

1. **时效目标**：建议第一版定位 1 分钟级盘中信号，而不是秒级/Tick 级盯盘；否则数据源、存储和告警架构需要完全升级。
2. **覆盖口径**：建议“历史涨跌停池负责发现候选，完整行业成分股负责确认传导”；如果确认层也限定在历史池，只能称“池内传导”。
3. **复盘产物**：建议第一版包含可保存的“次日关注清单”，但不包含买卖建议与自动交易。
