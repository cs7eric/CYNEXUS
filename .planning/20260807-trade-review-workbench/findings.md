# Findings

- Portfolio trades already persist `symbol`, `instrumentType`, `side`, `tradedAt`, `quantity`, and `price`.
- The stock-chart domain already returns intraday 1m bars from ClickHouse and supports aggregation periods.
- Local TDX 1m ingestion is already scheduled through `kline_1m_tdx_close` / `sync_kline_minute`.
- Existing worktree changes include Market Indicator replay APIs and UI components. This task must integrate with, not replace, those changes.
- CodeGraph impact shows `StockChartQueryDomainService` is highly shared. The workbench should consume its existing intraday contract instead of extending it.
- `MarketIndicatorQueryDomainService` already has replay timeline support and is the correct source for 30-second replay events.
- Scheduler already exposes a management trigger path; the local TDX close job can be invoked through the existing scheduler contract.
- The replay timeline currently filters industry snapshots by `industryCode`, but replay events remain global and are capped at 1000 rows. Industry stock status and first-limit-up analysis therefore needs an industry-aware event filter using the latest constituent snapshot at or before the replay date.
- The trade-review industry lower slot now has Capital/THS constituent loading and cursor-safe rendering in progress; it still needs a dedicated industry timeline request so the slot is not backed by the global event sample.
- Live verification found the root cause: `/stock-chart/stock-sectors` only reads `sec_stock_sector`, which contains TDX topic memberships but does not reverse-join THS constituent snapshots. `stock_meta.industry` and `sectorIndex*` are also empty for sampled stocks. THS already has direct reverse mappings: e.g. `000001 -> 881155 银行`, `600519 -> 881273 白酒`, `688981 -> 881121 半导体`, `300750 -> 881281 电池` through `tdx_ths_industry_mapping`.
- Industry Application target names use TDX labels while fund-flow rows use THS labels (for example `酿酒` vs `白酒`, `电气设备` vs `电池`), so the stock-sector response should expose the THS mapped name/code as the primary industry association and retain TDX metadata in `topicId`/source.
- Day-level overlay loss has two frontend causes: historical industry K-lines are requested only when the intraday `industry` response exists, and historical overlay rendering is also gated by non-null intraday `industry`/`index` objects. The fixed index target and resolved Industry Application target are sufficient to load/render historical context without those intraday payloads.
- The day-level mock only stores repeated leader names, not dated stock pools. It needs day-specific coded members per ladder height plus a previous-day limit-up pool. A dedicated mock intraday series can render the following trading day's mini chart without calling real services during this design phase.
- The outer page owns `tradeDate`; `TradeReviewPanel` currently receives it as a read-only prop. Day-to-minute drill-down therefore requires an `onTradeDateChange` callback, switching the panel to timeshare/1m before reloading the selected date.
- The active day-level renderer is `RealDailyView`, not the earlier mock `DailyView` (`void DailyView` keeps the latter dead). Consequently the visible controls still used 5/10/20 days and the fetch window was only 45 calendar days; earlier 60-day/custom work modified the inactive path. The active path must own the 20/60/120/custom controls and request a sufficiently long history.
- Market Pulse supports `20d`, `60d`, `120d`, and `1y`. Custom day windows can map to the smallest covering Pulse range while the sentiment summary request uses an explicit calendar-date interval.
- The visible `RealDailyView` still renders `latest.ladder.leaders` from the real pulse payload. The new dated mock ladder `members` are never used, which is why every height appears to repeat the same leader names.
- Release verification shows `/api/market/stock-chart/klines` returns zero rows for both `target_type=index&symbol=000001` and `target_type=sector&symbol=880380`; that path falls back to Release-local TDX `.day` files, which are not mounted there.
- `/api/market/industry-application/kline` returns populated ClickHouse daily history for both `index/000001` and `industry/880380` through `clickhouse.daily_raw`. Historical context overlays must use this serving path instead of the stock-chart daily endpoint.
- The day-to-minute action currently changes date/period but does not start from the first minute because the date-loading effect resets `playing` and the generic bar effect places the cursor at the last bar.
- Data-contract research (2026-08-10): `build_limit_emotion` already persists a market-wide daily summary, per-stock limit-emotion rows, ST-aware limit thresholds, current/previous streaks, promotion/broken-streak flags, and a streak distribution. It is the correct base for end-of-day ladder, promotion, broken-board, and previous-day feedback, but it does not yet materialize an as-of industry/concept aggregation or first/last seal times.
- CodeGraph CLI is present and current, but its symbol-search command is `codegraph query`, not `codegraph search`; use `query` for subsequent impact inspection.
- `market_limit_daily_stocks` is intentionally compact: date, identity, category, streak, close change %, and price limits only. The existing payload JSON repeats these values. It cannot support first/last seal, open-board count, sealing capital, or exact daily feedback without a new stock-fact table or extension.
- `market_indicator_refresh` captures market quotes and event transitions intraday, then aggregates industry snapshots by the latest THS membership. It already carries first limit-up time/event, touch/seal/open transitions, breadth, and limit counts; however, it is an event feed, not a complete historical day-by-day stock fact source, and it must use the membership snapshot valid for the replay date.
- The existing timeshare archive is appropriate for mini charts: ClickHouse stores canonical session points (price, avg price, volume, turnover) by day/target/slot, while Redis stores a complete selected-target series with a one-week TTL. Its selection already covers all up/down-limit stocks and per-THS-industry gainers/losers, so it should be read rather than duplicated by the new market-state mart.
- THS constituent snapshots retain per-stock daily ranks and market fields (price, change, speed, turnover, volume ratio, amplitude, PE) but have no explicit industry-name column; names must resolve via the THS/TDX mapping valid on that date. The existing indicator repository incorrectly defaults to the latest membership for live capture, which is acceptable for current monitoring but must not be used for historical review aggregation.
- EastMoney has a date-addressable `limit_pool` source: `zt` includes first/last seal time, seal fund, break count and board statistics; `zb` includes first seal and break count; `dt` has last seal/open count; `zbgc` carries yesterday-limit feedback fields. These are the richest source for EOD detailed pool facts and can be retained as raw provider payload plus normalized columns.
- Research read attempted a wrong path (`cynexus-data/src/cynexus_data/sql/...`) before correcting it to `cynexus-data/sql/...`; no state was changed by the failed read.
- TDX capability is sufficient to capture a daily historical constituent snapshot: `eltdx.f10.theme_market` exposes the `constituents` section for all TDX-56 industry seeds, but the current job stores it only as a JSONB TDX sector detail. A normalized, date-versioned TDX constituent table is required before a historical THS+TDX union can be calculated safely.
- The current THS constituent job has a useful carry-forward mechanism that records provenance. Reuse the same effective-date convention for TDX snapshots and for the union materialization; never fall forward from a later date.
- Attachment validation (2026-08-10): confirmed. `radarState` calls `repository.getBreadth(tradeDate)` without `asOf`; only the count of a 50-event sample is truncated. `radarLimitLadder` has no `asOf` parameter and returns the latest snapshot ordered by change percentage, not a height ladder. The current MarketStateTab consequently front-end-composes EOD emotion with latest breadth and estimates intraday broken/promotion metrics from a bounded event list. Replace this entire composition with one Trade Review Market State read model.
- Acquisition conclusion (2026-08-10): post-close review should treat locally ingested full-market TDX 1m bars as the canonical replay grid, with daily K/stock-rule metadata supplying prior close, limit prices and final streaks. Market Indicator remains the only live intraday event source and should be persisted as capture batches, but it must not be queried live to reconstruct replay state. Display timeshare is an independent selected-symbol presentation dataset, never an input dependency for global/industry state calculation.
