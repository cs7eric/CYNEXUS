# 交易多维分析实施计划

## 目标

在现有个人持仓、交易记录、FIFO 账本、每日绩效和复盘能力之上，建设交易分析中心。第一阶段只读、可追溯、对数据缺口诚实；后续补充交易计划和账户资金快照，支持风险单位（R）、预期管理和组合风险预算。

## 范围与非目标

- 范围：股票/ETF 的已确认交易、完整交易轮次、持仓、账户绩效、复盘和交易计划。
- 非目标：第一阶段不自动下单、不改变现有账本口径、不把未闭合持仓当成已完成交易、不在缺少资金流水时声称真实年化收益。

## 阶段

- [completed] 1. 数据审计与指标口径冻结
- [completed] 2. 交易轮次匹配与分析领域模型
- [completed] 3. 后端查询 API、缓存/刷新和数据质量标记
- [completed] 4. 前端交易分析中心与现有持仓页集成
- [pending] 5. 交易计划、预期管理和复盘字段增强
- [pending] 6. 账户快照、组合风险和基准收益
- [pending] 7. 测试、版本同步、Release 验证与上线验收

## 关键决策

- 已完成交易按同一标的、同一 instrumentType 的 FIFO 买卖匹配；卖出不足时保留 unmatchedQuantity 警告。
- 盈亏均以净手续费后的金额计算；除非接入税费字段，不伪造税费精度。
- 胜率只统计 completed round；未平仓交易单独显示浮动结果。
- 第一阶段的仓位占比使用当前/历史可估算市值，并显示 valuationStatus；缺少资金流水时收益率标记为 portfolio-based。
- 聚合计算放在 domain/application 查询链路，UI 只负责筛选、展示和空/缺失状态。

## 验收总表

- 所有指标均能追溯到交易轮次或每日快照，并返回 dataQualityWarnings。
- 过滤条件（时间、标的、股票/ETF、策略、标签、盈亏状态）在 API 和 UI 口径一致。
- 缺少配对、价格、资金快照时不报错、不补零冒充真实数据。
- 关键领域测试覆盖 FIFO、部分卖出、加仓、跨日、手续费、未闭合和异常数据。
- Maven/UI 版本保持相同 `x.y.z-SNAPSHOT`；完成规定的构建、测试和 Release 验证。
